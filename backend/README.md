# 本地菜谱导入服务

Python 3.10+，仅使用标准库，无需 pip 安装。程序只监听 `127.0.0.1:8765`，不适合直接部署上线。

## 启动

在 PowerShell 中运行：

```powershell
.\backend\start.ps1
```

保持终端运行。若系统限制脚本运行，可以直接启动 Python：

```powershell
python backend/server.py
```

按 Ctrl+C 停止。若提示端口被占用，检查是否已经有该服务在运行，不要重复启动。

## 微信开发者工具

1. 本地项目设置已将 `urlCheck` 设为 false，用于请求本机 HTTP 服务。若工具没有刷新设置，在“本地设置”勾选“不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书”。这是开发阶段配置，上线前需要合法 HTTPS 后端和权限管理。
2. 重新编译 → 添加菜谱 → 链接导入（网页提取）。
3. 粘贴下厨房菜谱链接，点击开始解析。
4. 成功时进入编辑表单，检查食材、用量、步骤，点击确认保存。
5. 失败时显示实际错误，不自动生成菜谱；可手动填写。

手机上的 `127.0.0.1` 指手机自身，所以当前只支持电脑模拟器导入。现有本地菜谱与清单功能仍可在手机使用。

## API

- `GET /health`：服务状态。
- `POST /api/import`：JSON 请求 `{"url":"https://www.xiachufang.com/recipe/数字/"}`，带 `X-Recipe-Client: local-miniprogram`。成功返回 `draft`、`warnings`、`method`、`aiUsed: false`。失败返回中文 `error`，不会保存数据。

该请求头仅限制普通浏览器跨站请求，不是家庭成员身份认证。本服务无共享数据库，确认保存仍由小程序写入当前设备。

## 已知限制

- 当前为网页结构提取，没有大模型，也没有正文 AI 解析功能。
- 真实样例此前可被普通客户端读取，但本次 Python 请求返回 404，另一次普通客户端请求进入滑动验证。不能承诺两个样例实时成功。
- 不绕过验证码，不跟随网站重定向，也不自动轮换客户端或代理重试。
- 只支持已明确列出的下厨房域名，校验路径后统一从主站首次请求。
- 缺失用量留空。无法拆分的 schema 食材保持整行并警告人工核对，不猜测数字。
- 份量仅映射文本，耗时暂不转换；分类默认为家常菜，确认时可修改。
- 不下载图片、不保存完整网页，返回的草稿仅在前端会话内保留；人工确认后才进入本地正式菜谱库。

## 验证

在本目录执行 `python -m unittest -v test_importer test_server`。测试包括 URL 范围限制、验证码、字段缺失、结构化数据后备提取和真实本机 HTTP 接口；成功网页测试使用合成样例，不代表下厨房实时访问成功。

`check_samples.py` 单独执行真实链接只读验证，仅输出字段计数和错误，不保存网页。
