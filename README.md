# 家庭菜谱微信小程序

一个面向家庭场景的微信小程序原型，覆盖菜谱管理、买菜清单、网页菜谱提取、AI 文本整理、联网搜索和可选云端同步。项目重点是把“收集—人工确认—保存—采购”做成可验证、可回退的数据流。

> 当前状态：核心本地流程、后端接口和自动化测试已完成；DeepSeek、Tavily 与 CloudBase 已在本机配置，但各项真实联网能力仍需按部署环境验收。项目尚未正式发布。

## 功能

- 菜谱列表、菜名/食材搜索、分类筛选和详情展示
- 手动新增与编辑，本地持久化并保留来源
- 买菜清单、同单位数量合并、已购状态和手动条目
- 粘贴正文，经 DeepSeek 整理为结构化草稿，人工确认后保存
- 通过 Tavily 搜索公开页面，再进入 AI 整理与确认流程
- Python 服务提取受支持网页中的结构化菜谱信息
- 可选 CloudBase 后端，包含访问令牌校验、版本冲突检测和清单事务
- 对无效 URL、验证码页面、字段缺失、重复请求和并发更新进行失败处理

## 技术栈

| 层 | 技术 |
| --- | --- |
| 小程序 | 微信小程序原生 JavaScript、WXML、WXSS |
| 本地数据 | `wx.setStorageSync` / `wx.getStorageSync` |
| 后端 | Python 3.10+、标准库 HTTP 服务 |
| AI 与搜索 | DeepSeek API、Tavily API（后端调用） |
| 云端 | CloudBase HTTP API、MySQL 兼容数据表与事务 |
| 测试 | Python `unittest` |

## 架构

```text
微信小程序
├─ pages/                 列表、详情、编辑、导入、搜索、设置、买菜清单
├─ data/library.js        校验、本地存储与编辑合并
├─ data/shopping.js       清单存储、数量合并与状态切换
└─ data/cloud.js          可选云端 API 适配
        │
        ▼
Python 后端
├─ server.py              本地网页提取接口
├─ deepseek_recipe.py     文本结构化与结果校验
├─ search_recipe.py       搜索、候选过滤、缓存与 AI 整理
├─ cloud_app.py           云端 HTTP 入口与鉴权
└─ cloud_store.py         乐观锁、数据校验与清单事务
```

AI 或网页提取结果始终先进入可编辑草稿。只有用户确认后才保存；失败时不伪造内容，也不绕过目标网站的访问限制。

## 我如何使用 Codex

项目采用“需求拆解—小步实现—自动验证—人工验收”的实际工作流：

1. 我先把需求拆成列表/详情、编辑、买菜清单、导入、搜索和云同步等模块，并明确每阶段的验收条件。
2. 我让 Codex 根据现有代码实现单个模块，再逐项检查空菜名、缺失食材、重复保存、不同单位合并和未保存离开提醒等边界。
3. 调试网页导入时，我与 Codex 根据真实 HTTP 结果区分 404、验证码和结构化字段缺失；遇到站点限制时保留失败信息，没有把合成样例当作真实成功。
4. 接入 DeepSeek、Tavily 和 CloudBase 时，我把密钥留在后端环境文件，并让 Codex 补充输入限制、来源保留、缓存、鉴权和并发版本检查。
5. 每轮改动后运行 `unittest`，再在微信开发者工具中检查页面和本地存储；README 只记录已经实现且能解释、修改和演示的内容。

我与 Codex 参与代码生成、重构建议、错误定位和测试补充；需求取舍、验收标准、真实联调结果和最终确认由我负责。

## 运行

1. 使用微信开发者工具导入本目录。
2. 在本地配置中填写自己的小程序 AppID。
3. 编译项目；不启用后端时，本地菜谱和买菜清单仍可使用。

本地后端：

```powershell
python backend/server.py
```

服务默认监听 `127.0.0.1:8765`。模拟器可访问本机地址，手机不能直接使用电脑的 `127.0.0.1`。

配置文档：

- [DeepSeek 配置](docs/deepseek-setup.md)
- [搜索配置](docs/search-setup.md)
- [云端部署](docs/cloud-deployment.md)
- [网页导入可行性记录](docs/import-feasibility.md)

不要提交 API Key、访问令牌、AppSecret、私有项目配置或本机 `.env` 文件。

## 隐私与版权边界

- 仓库不应包含 `.env`、API Key、家庭访问令牌、私有项目配置或真实用户数据。
- 内置演示菜谱由本项目编写，不是抓取形成的正式菜谱库。
- 外部网页只用于用户主动导入或搜索候选；保留来源，遇到验证码或限制即停止。
- 公开前可将家庭称谓替换为中性名称，减少个人信息暴露。

## 已知限制

- 本地数据不会自动跨设备同步，清理小程序数据会丢失。
- 本地提取服务仅用于开发预览，不适合直接部署到公网。
- AI 整理结果仍需人工核对。
- 尚未完成微信正式发布、生产监控和完整真机兼容测试。
