## 结论及实现建议

- 两个样例支持继续开发内容提取原型；尚未完成字段级提取或内容准确性核验。
- 未发现或接入官方菜谱 API；目前验证的是公开网页读取能力。
- 对受支持的下厨房域名和 `/recipe/数字/` 路径进行校验，提取 ID，使用统一主站地址作为首次获取目标，保留原始来源链接。
- 不能仅依据 HTTP 200 判断成功，必须识别验证页、登录页和空内容。
- 对明确返回验证码或访问限制的请求停止自动获取，不自动轮换域名、代理或重试以规避限制，提供粘贴正文入口。
- 主站存在 Recipe 结构化数据标记；下一步检查其具体字段，能直接映射的字段优先映射，再按需让模型整理，减少不必要的模型调用。
- 始终展示可编辑草稿，经用户确认后才正式保存。
